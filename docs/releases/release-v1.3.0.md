# Duck on Desk v1.3.0

新增「动作商城」，并把第二课改为原样复用官方 Roulade 配方。

## 动作商城

- 设置菜单「动作 → 动作商城」打开独立窗口，目录来自 Hugging Face 上带 `microduck-policy` 标签的仓库（2026-09-16 实测 34 个）。标签只用于发现，不代表可信。单次 `?full=true` 请求即取得每个仓的当前 commit 与文件清单，因此在下载任何权重之前就能判断可用性；结果本地缓存 6 小时，离线时回落缓存并明示已过时。
- 兼容性判定依据社区既有的 `manifest.json` 约定，认稳定字段 `model_api`（`schema_version` 各作者自行编号，跨仓无意义）。分四档：可直接使用 8、需要手动映射 17、未声明契约 8、不兼容 1。缺少 manifest 或声明了未知 `model_api` 的仓不被拒绝，只标为未声明契约。`robot.model` 按首个词元识别机器人，其余词元视为机身限定词，滚轮与高跷一类形态不开放一键使用。
- 下载完整性以 Hub 自身的 Git LFS 记录为锚：LFS 的 `oid` 即文件内容 sha256（实测 33 个带 `policy.onnx` 的仓全部适用）。确切体积与摘要在取第一个字节之前即已知，不符者永远不会落到最终路径。作者 manifest 里的 `eval` 数据不参与任何校验。权重存入用户级 Hugging Face 缓存 `~/.cache/huggingface/duck-market/<owner>/<repo>/<commit>/`，安装包内不含任何 ONNX。
- 「已下载」与「已加入桌宠」是两个状态，不能跳过：前者只表示权重落盘且摘要正确；后者要求用户在本机实验室里看着它跑完整段并确认接受。试播计量取自运行时真实的控制步数、输出路数与有限性，不取自任何声明。这与实验室对本地训练动作的既有规则一致。`installed.json` 每次读取重新校验，手工编辑的条目会被丢弃。
- 只有零指令的有限时长动作可以播放。其余策略的 13 个指令槽位含义由作者自定，与桌宠的行走指令不是同一套，喂错不会报错、只会产生不可预期的动作，因此不进入播放路径——本仓自身即有先例：行走、坐站、啄地、动作播放、滚轮五种情形对前 3 个槽位有五种不同定义。速度步态可下载、可在实验室作为行走策略试用，暂不能替换桌宠的行走策略。
- 预览视频经新增的 `pet-market://` 协议代理，商城窗口因此保持 `default-src 'self'` 的 CSP，页面脚本无法直接访问 huggingface.co。代理只接受固定 URL 形状、钉死 commit、限定媒体类型，并转发 Range 以支持拖动播放。
- 修复：新增协议时若第二次调用 `registerSchemesAsPrivileged`，会保留 `standard` 列表但替换 `secure`/`fetch`/`cors`，致使 `pet-model://` 失去 fetch 与 cors 权限、桌宠取不到行走策略而始终不出现，且全程不抛错。现将全部特权 scheme 集中在 `src/shell/privileged-schemes.js` 一次注册，两个协议模块不再各自导出注册函数。

本版商城不含：上传本地训练成果到 Hub、精选索引、通用指令映射界面、把下载的步态应用到桌宠（后者需要与本地训练策略同等的对照评测门槛，不应降标准）。

## 第二课：官方 Roulade 配方

- 第二课改为直接调用官方注册的 `load_env_cfg` / `load_rl_cfg` / `load_runner_cls`，任务 `Mjlab-Roulade-Flat-MicroDuck`，来源 `pollen-robotics/microduck_rl` 固定提交 `53b8971`。不重写奖励、碰撞模型或课程表。基线为随机初始化、在线归一化、探索标准差 1.0、学习率 0.001、24 步/轮、10000 轮、5 秒回合。
- `training/roulade-official-reward.py` 显式列出全部 20 项初始权重、中文作用与 4 项奖励课程表，界面从同一文件生成官方基线对照表，不冒充实时权重。新默认配置逐项与固定版本官方环境核对（`test_reward_config.py`）。用户对学习率、步数、种子、轮数或奖励的修改都记录在任务配置里，属于自定义实验，不再称为官方默认。
- 训练每 200 轮及结束时保存 10 秒姿态回放，可在界面回看，用于观察低头、越过头顶、起身与站稳这几个阶段，而不是只看奖励曲线。
- 20 环境、站立起步的验收是**应用自定义的只读评测**，不是官方成功率承诺；它使用独立环境，不修改训练环境。
- 前滚翻加入桌宠动作库走的是显式用户确认（`admission: user-confirmed-v1`），**不等于自动验收通过**；条目的 `native_evaluation_passed` 保持真实值，不被确认动作改写。
- 旧的步态微调路径保留为 `experimental-v1`，续训旧检查点仍属旧实验，不会被伪装成随机初始化的官方基线。

`AGENTS.md` 相应新增「Robot Lab course development」一节，把「先查官方是否已有」「优先复用官方配方」「区分脚本存在 / 链路跑通 / 动作学会」写成硬约束。

## 已知限制

Windows 安装包仍未代码签名，开启「智能应用控制」的机器会拦截已安装的可执行文件——与第一课 `warp.dll` 是同一道闸门。关闭该功能不可逆，需重置系统才能恢复；从源码启动不受影响，因为执行的是 Electron 官方预编译二进制。根本解决需要代码签名证书。

商城设计与实测记录见 `docs/plans/action-market_00_动作商城设计方案.md`，第二课配方来源与偏离记录见 `mcp/robot-lab/OFFICIAL-ROULADE.md`。
