## 原因排序：事实与推断

1. **主要奖励难以获得。** `headstand-reward.py` 将头撑、无脚／其他身体接地、腿部高度、重心对齐、倒置程度、稳定性与关节范围相乘。部分条件未满足时整项归零；即使接触正确，角速度 3 rad/s 单独就使稳定系数降至 exp(−18)，约 1.52e-8。严格组合适合验收，但作为主要学习信号，缺少通往目标的中间奖励。旧版横躺刷分被堵住了，学习可达性没有一起解决。
2. **总从站立开始，没有课程或参考轨迹。** `action_environment.py` 每段 8 秒从站立重置，仅有微小初始扰动。策略需要自行发现接触、转移重心、抬腿、保持的组合。日志证明本次完全没有有效倒立样本；这是首要改进方向，不是宣称 PPO 理论上无法从零探索。
3. **翻转与保持共用惩罚和噪声。** 首次翻转进展每段最多 +0.5，而运动／指令扣分每步发生。翻转需要运动，保持需要安静，应按阶段区分。当前 50 Hz、固定 .3 rad（约 17°）的独立指令噪声不随熟练度降低；这里是指令噪声，不是机器人每步实际转动 17°。其影响需要对照验证。
4. **行走先验及动作限幅可能限制探索。** `policy.py` 冻结行走网络，只训练有界残差，再硬限幅均值。行走先验未包含倒立示范；复播出现大量限幅，提示需要检查饱和与残差表达能力，但还不能认定它是唯一根因。奖励新增的接触／重心／保持历史也未全部进入原有 61 维策略观测，可作为后续可观测性对照。
5. **Duck 的可行支撑与进入轨迹尚未充分验证。** 之前九组预置倒置状态＋固定关节目标最多支撑 0.84 秒；既不证明两秒倒立不可能，也不能当成可行两秒目标已验证。没有手臂的 Duck 必须先找到自身结构允许的头撑构型。

PPO 裁剪的是新旧策略概率比（当前 .8～1.2），不是把奖励裁剪到 1。现有证据首先指向训练信号和状态覆盖，不支持归因于预览渲染、MPS 算力或“5 分无效”。

## 建议的下一轮实验

1. 在当前物理／电机约束内寻找可稳定保持的头撑目标，记录接触、重心、关节角与速度；先从接近目标姿态训练抗小扰动保持，不能把初始化成倒立算作站立起步成功。
2. 验证保持可学后，建立适配 Duck 的少量中间参考姿态／可跟踪轨迹。混合从各阶段初始化，逐渐提高站立初态占比；用实际接触与姿态推进阶段。
3. 过渡阶段奖励朝参考状态靠近，保持阶段奖励稳定与连续时间，降低保持阶段探索噪声。姿态、重心、关节与接触分别记录，避免所有有用梯度被乘法门槛抹去，同时防止重复翻滚刷进展。
4. 分别对照固定行走底座／动作专用策略、固定／渐退噪声，判断饱和和探索的影响；先做可解释的小实验，不立即投入又一次相同长训。
5. 最终仍按原生三段＋WASM 一段从站立出发、无辅助、结尾连续两秒严格倒立验收；通过后再做恢复正立课程。先不承诺新默认参数或成功轮数。

方法可以在现有 MPS／CUDA 兼容训练代码中实现；CUDA 仍待实机。增加采样吞吐不能替代目标姿态的物理可行性与有效学习路径。
